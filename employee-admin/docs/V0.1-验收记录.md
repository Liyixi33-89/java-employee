## 5. 本阶段踩到的真实问题与修复

1. **PowerShell 管道破坏中文输入**
   `"张三" | java Main` 会让姓名变成 `??`——PS 5.1 管道按控制台代码页转码。
   修复：验证脚本改为写 UTF-8 无 BOM 文件，再用 `cmd /c java ... < file` 重定向。

2. **带 BOM 的粘贴内容被判为非法输入**
   从网页/文件粘贴的 `\uFEFF` 会让 `1` 变成 `"\uFEFF1"`，看着是 1 却被拒绝。
   修复：`ConsoleMenu.normalize` 统一剔除 `\uFEFF`、`\u200B` 并 `trim()`。

3. **修改/删除绕过工号格式校验**
   初版先查存在性再校验，导致空工号被报成「工号不存在」——语义错误。
   修复：新增 `EmployeeService.requireExisting`（先格式、后存在性），
   修改与删除共用同一入口。

4. **编辑 `.ps1` 后丢失 UTF-8 BOM**
   PS 5.1 按 GBK 解析无 BOM 脚本，中文注释导致语法错误。
   修复：编辑脚本后统一用 `UTF8Encoding($true)` 回写 BOM。

## 6. 复盘：设计取舍

| 决策 | 理由 | 代价 |
|---|---|---|
| 工号设为 `final` 不可变 | 工号是外部业务标识，改动会让将来的审计/关联引用失效；换号语义上应"删除重建" | 换号操作需要两步 |
| 唯一性既靠 `Map` 键又显式校验 | 换数据库后约束由 DB 承担，业务层要保持同一套错误文案 | 少量重复判断 |
| 姓名上限 20 字符 | 覆盖中文姓名与拼音全名，避免表格展示溢出 | 特殊长名需放宽 |
| 删除要求输入 `DELETE` | 控制台无撤销，误删代价高于多敲一次 | 略繁琐 |
| 搜索空关键词直接拒绝 | 静默返回全量会掩盖用户误操作 | 与"列出全部"功能重复 |
| `Locale.ROOT` 做小写化 | 土耳其语环境下 `I`→`ı` 会让 `Alice` 匹配失败 | 无 |

## 7. 阶段边界声明

- 数据仅在内存（`LinkedHashMap`），进程结束即全部丢失。
- 单进程、单用户，无并发控制；同一工号并发新增的竞态不在本阶段范围。
- 无部门、状态、权限、审计（V0.3—V0.5 逐步引入）。
- 无单元测试框架（V0.2 引入 JUnit）；当前靠 `run-samples.ps1` 的 9 组场景断言验证。
- 场景脚本只验证"输出包含期望片段"，不验证内部状态与并发行为。
- 无日志、无持久化、无打包部署。

以上均为路线设定的阶段边界，不是隐藏缺陷。
